# Module 5: Test it and review the changes
`🟡 Moderate` · 10 min

AI sounds confident even when it's wrong. **You** are responsible for what you submit, so check it.

## Step 1: Try to break it

Open your app and try:
- [ ] Every button
- [ ] Leaving inputs empty
- [ ] Silly input: letters in number boxes, negative numbers, a huge number
- [ ] Clicking things twice, fast
- [ ] Making the browser window narrow (like a phone)

Found a problem? Describe it to the AI and fix it, one problem at a time.

## Step 2: Ask for a review

Start a **new** conversation (a fresh pair of eyes) and ask:

> Review the code in projects/<my-username>/ as a careful senior developer. List any bugs, confusing code or security problems, in plain English. Don't change anything yet.

Fix anything important it finds.

## Step 3: Review the changes in GitHub Desktop

Open GitHub Desktop and look at the **Changes** tab (left side).

- Every file listed should be inside `projects/<my-username>/`. **If anything else is listed, don't commit it.** Right-click it → **Discard changes**.
- Click a file to see what changed: **green** lines are added, **red** removed.
- You don't need to understand every line, but skim it. Does it roughly make sense? Any passwords, keys or personal info? (There shouldn't be.)

## ✅ Checkpoint

- [ ] I tried to break my app and fixed what I found
- [ ] A fresh AI session reviewed the code
- [ ] GitHub Desktop's Changes list only shows files in my folder
